# プロダクト要求定義書

## プロダクト概要

### 名称

**YouTube Thumbnail Maker**（仮称）

### コンセプト

- **迷わない**: 大見出しに必要な設定だけを提供する
- **読みやすい**: 行ごとの文字サイズと強い縁取りを、スライダーだけで決められるようにする
- **持たない**: 入力画像と生成結果を端末外へ送信・保存しない

### 目的

日本語のYouTube動画制作者が、画像編集ソフトの細かな操作を覚えずに、強い縁取りのある大見出しを使った1280×720サムネイルを短時間で作れるようにする。

## ターゲットユーザー

### プライマリーユーザー

- YouTube動画を個人または小規模チームで制作する人
- サムネイル制作に毎回同じ文字装飾を使う人
- 高機能な画像編集ソフトより、少ない操作で一貫した出力を求める人

## 解決する課題

- 文字数が変わるたびにフォントサイズと改行を手作業で調整する必要がある
- 縁取りを含む大きな日本語文字を、画像内へ収める調整が難しい
- 単発の画像加工にサーバー送信やアカウント作成を必要としたくない

## 成功指標

利用解析は初期実装へ入れず、手動ユーザーテストと技術検証で測定する。

- 初見の利用者が、画像選択からPNG保存まで60秒以内に完了できる
- 1〜60文字の受け入れ用サンプルが、指定した安全領域からはみ出さない
- 出力画像が常に1280×720になる
- 入力画像、入力文字列、生成画像を含む外部通信が0件である

## ユーザーストーリー

| ID | ストーリー |
| --- | --- |
| US-01 | 動画制作者として、端末の画像を選びたい。素材を外部へ預けずに編集するために。 |
| US-02 | 動画制作者として、見出しを入力するだけで読みやすく配置したい。毎回のサイズ調整を減らすために。 |
| US-03 | 動画制作者として、1枚の中で白・黄・赤を使い分けたい。強調したい語を目立たせるために。 |
| US-04 | 動画制作者として、行ごとの文字サイズをスライダーで変えたい。画像ごとに強調度を調整するために。 |
| US-05 | 動画制作者として、完成画像をPNGで保存したい。そのままYouTubeへ設定するために。 |

## 受け入れ条件

### F-01: 背景画像の読み込み

- [ ] JPEG、PNG、WebPを読み込める
- [ ] ファイル選択と、プレビュー・背景画像パネルへのドラッグ＆ドロップの両方で読み込める
- [ ] 20MiB超または4000万画素超の画像を、理由付きの日本語メッセージで拒否する
- [ ] 縦横比を保ったまま1280×720へカバー配置する
- [ ] 拡大率を100〜300%、横縦の位置を-50〜50%で調整できる
- [ ] 画像内容をサーバー、解析、ログへ送信しない

### F-02・F-03: 見出しと行レイアウト

- [ ] 入力欄ごとに30文字まで入力でき、全て空の場合は書き出しを無効にする
- [ ] 1行目は入力欄①、2行目は入力欄②→③の順で連結する
- [ ] 空の行は詰める
- [ ] 行は画面最下部へ寄せて積み上げ、左右は中央揃えとする
- [ ] 行幅が領域幅を超えても自動改行・自動縮小を行わず、左右へはみ出させる

### F-04: 文字スタイル

- [ ] 1行目は白塗り `#FFFFFF` で描画される
- [ ] 2行目前半は黄塗り `#FFD400`、後半は赤塗り `#FF3B30` で描画される
- [ ] 縁は全色共通で黒 `#111111` となる
- [ ] 行内で色が切り替わる位置でも、縁が隣の文字の塗りを削らない
- [ ] 縁の角が不自然に尖らない

### F-05: 文字サイズ・縁取り調整

- [ ] 1行目・2行目の文字サイズを個別に24〜200pxで1px単位で調整できる
- [ ] 既定は1行目75px、2行目93pxである
- [ ] 縁幅をフォントサイズの10〜30%で調整でき、初期値は18%である
- [ ] 現在値を数値でも確認できる

### F-06: プレビューと書き出し

- [ ] 入力・文字サイズ・縁幅の変更がプレビューへ反映される
- [ ] 操作UIが背景画像と文字の2パネルに分かれ、それぞれ折りたためる
- [ ] 出力が常に1280×720 PNGになる
- [ ] 元画像のEXIFなどのメタデータを出力へ引き継がない
- [ ] 主要操作をキーボードだけでも実行できる

### F-06b: Xへのシェア

- [ ] 書き出し可能なときだけシェアボタンを押せる
- [ ] ファイル共有対応環境では、生成PNGを添付した状態で共有シートを開く
- [ ] 非対応環境では X の投稿画面を開き、画像を手動で添付する旨を案内する
- [ ] いずれの経路でもハッシュタグとツールURLが本文へ含まれる
- [ ] 画像と入力文字列を自サーバーへ送信しない
- [ ] 共有をキャンセルしてもエラー表示しない

## 技術要件

| レイヤー | 技術 |
| --- | --- |
| UI | バニラTypeScript、HTML、CSS |
| 画像処理 | Canvas 2D API、`createImageBitmap` |
| ビルド | Vite |
| バックエンド | なし |
| データベース | なし |
| 認証 | なし |
| 配信 | 静的ホスティング。サービスは公開時に選定 |

編集状態はメモリ内だけに保持し、初期実装ではLocal Storageも使用しない。

## 非機能要件

| 項目 | 要件 |
| --- | --- |
| パフォーマンス | デコード後の文字変更を、一般的なデスクトップで100ms以内を目標に反映する |
| 対応環境 | 現行のChrome、Edge、Firefox、Safariを対象とする |
| レスポンシブ | 幅360px以上で基本操作とプレビュー確認ができる |
| アクセシビリティ | 入力へラベルを付け、フォーカス表示と十分なコントラストを確保する |
| プライバシー | ユーザーが選んだ画像と入力文字列を端末外へ送信しない |
| 可用性 | ビルド済み静的ファイルだけで動作し、サーバー処理に依存しない |
| 保守性 | レイアウト計算とCanvas描画をUIから分離する |

## スコープ外

- AI画像生成、文言生成、背景除去
- アカウント、履歴、クラウド保存、共同編集
- 複数キャンバスサイズと動画出力
- 汎用レイヤー、図形、スタンプ、自由変形
- F-07の詳細編集はMVP受け入れ対象に含めない
