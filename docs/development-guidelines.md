# 開発ガイドライン

## 基本原則

- ユーザーの目的に必要な最小機能を優先し、汎用画像エディターへ拡張しない
- ユーザー画像と入力文字列を端末外へ送信・保存しない
- UI、純粋な計算、ブラウザ固有処理の境界を維持する
- 仕様変更はコードだけでなく、対応する設計文書へ反映する

## TypeScript

### 書式

- インデントは2スペース
- 文字列はシングルクォート
- セミコロンは省略する
- 1行は100文字程度を目安とし、読みやすさを優先する
- `strict` 相当の型安全性を維持し、`any` を使用しない
- 未使用の変数、引数、到達しない分岐を残さない

### 命名

| 対象 | 規則 | 例 |
| --- | --- | --- |
| 変数 | camelCaseの名詞 | `occupationRate` |
| 関数 | camelCaseの動詞 | `calculateTextLayout` |
| Boolean | `is`、`has`、`can`で始める | `canExport` |
| 型・interface | PascalCase | `EditorState` |
| 定数 | UPPER_SNAKE_CASE | `CANVAS_WIDTH` |

略語より役割が伝わる名前を優先し、`data`、`temp`、`obj` だけの名前を避ける。

### 関数設計

- 文字レイアウトと配置計算は、同じ入力に同じ結果を返す純粋関数にする
- DOM要素やCanvas Contextをグローバル変数として共有しない
- `File`、`ImageBitmap`、Blob URLの所有者と解放箇所を明確にする
- 予期される失敗は判別可能な結果または専用エラーで返す
- UIへ内部例外をそのまま表示しない

### コメント

- コードを読めば分かる処理を説明しない
- Canvasの座標変換、フォント計測、ブラウザ差への回避策など、理由が分かりにくい箇所だけ説明する
- 一時的な回避策には、削除条件または根拠を添える

## DOMとCanvas

- ユーザー入力は `textContent`、フォーム値、Canvas APIで扱い、`innerHTML` へ渡さない
- 入力要素には可視ラベルを関連付ける
- アイコンだけのボタンにはアクセシブル名とツールチップを付ける
- プレビューのCSS表示サイズとCanvas内部解像度1280×720を分ける
- 描画順序を背景、縁、塗りの順に固定する
- 状態変更をまとめ、同一フレームで重複描画しない

## CSSとUI

- CSSカスタムプロパティで色、間隔、寸法を定義する
- ツール画面として、プレビューと操作の反復作業を優先する
- カードを入れ子にせず、操作パネル内は区切り線と余白で整理する
- 文字プリセットは色見本付きのセグメント、占有率はスライダーを使用する
- 360px幅からデスクトップまで、操作や文字が重ならないことを確認する
- `prefers-reduced-motion` を尊重し、装飾目的の継続アニメーションを追加しない

## セキュリティ

- ファイル容量はデコード前、画素数はデコード後に検証する
- ファイル名、見出し、画像データをconsoleや外部通知へ出さない
- Object URLとImageBitmapを使用後に解放する
- 外部スクリプト、外部フォント、解析タグは設計レビューなしで追加しない
- npm依存追加時は、標準Web APIで代替できない理由、容量、ライセンス、保守状況を確認する
- 秘密情報をクライアントコードへ置かない

## テスト

### 優先順位

1. 文字レイアウトと画像配置の単体テスト
2. 状態更新からCanvas描画までの統合テスト
3. 画像選択からPNG保存までのE2Eテスト
4. 主要ブラウザと低性能端末の手動確認

### 必須ケース

- 見出し1文字、60文字、絵文字、結合文字、手動改行
- 占有率30%、50%、65%
- 横長、縦長、16:9の画像
- 容量超過、画素数超過、破損、非対応形式
- 画像の連続差し替え
- 幅360pxとデスクトップ表示
- 出力PNGが1280×720であること
- 入力データを含む外部通信がないこと

## 開発フロー

### セットアップ

```powershell
npm install
npm run dev
```

### 変更後の検証

```powershell
npm run typecheck
npm test
npm run build
```

同じ3コマンドを `.github/workflows/ci.yml` が `main` へのpushとPRで実行する。
Lintを導入した後は、対応するnpmスクリプトをこの節、README、CIへ追加する。

### Git

- `main` はビルド可能な状態を保つ
- 必要に応じて `feature/<目的>` または `fix/<目的>` を使う
- コミットメッセージはConventional Commits形式を使う
- `dist/`、`node_modules/`、入力素材をコミットしない

例:

```text
feat(editor): 見出しの自動レイアウトを追加
docs(requirements): 文字占有率の受け入れ条件を更新
```

## レビュー観点

- PRDの受け入れ条件を満たしているか
- 入力データを持たない設計を崩していないか
- 長文や巨大画像で停止しないか
- CanvasやObject URLのメモリを解放しているか
- 端末フォント差によるレイアウト崩れを考慮しているか
- 不要な設定や依存を増やしていないか
